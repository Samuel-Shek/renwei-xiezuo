# humanizer-zh

**拟人写作：把 AI 腔去掉，把人味留下。不改事实，不编故事。**

市面上「去 AI 味」工具很多，但不少会为了显得自然，把模糊信息改具体、把平淡经历加戏、把作者没说过的话写进去。humanizer-zh 的原则反过来：**先保真，再像人。**

---

## 它解决什么问题

AI 写出来的东西常有这些毛病：

- 「不仅…更是…」「不是…而是…」的公式化金句
- 「标志着重要转折」「未来可期」这类空泛抬高
- 「无缝、直观、强大」的宣传腔
- 「值得注意的是」「综上所述」的机械衔接
- 结尾硬凹升华，正文其实没信息量

但去 AI 味时更大的坑是**过度修改**：

- 为了「真实感」补出原文没有的数据、案例、对话
- 把简历上的「参与」改成「主导」
- 把合同里的「可能」改成「将会」
- 把本来就自然的口语改得更「文」
- 换掉术语、动了代码、改了标点体系

humanizer-zh 专门对付这两头：**该删的套话删干净，不该动的一个字不碰。**

## 工作机制

### 1. 先过场景边界

有些文本根本不该被「优化」：

| 文本类型 | 处理 |
|---|---|
| 只贴了文本、没说要做什么 | **不动**，问你要做什么 |
| 含密码 / API key / 私钥 | **拒收**，提示替换为 `[REDACTED]` |
| 对话、聊天记录、访谈 | 保留轮次和说话人，只删轮内套话 |
| 小说、散文、诗歌、剧本 | **逐字返回**，文学节奏不是 AI 腔 |
| 引号「」“”里的原话 | **逐字不改**，哪怕里面有套话 |

### 2. 模式与强度

- **保真模式（默认）**——只修明显 AI 痕迹，语域、立场、结构、信息全保留。你说「润色」「说人话」「改自然点」都走这条。
- **创作模式（需显式开启）**——只有明确说「启用创作模式」「深度重写」才允许动节奏和叙述顺序。即便如此，**事实锁仍然生效**。

强度只取最小必要：

| 强度 | 什么时候 |
|---|---|
| `no-op` | 找不到值得改的 AI 痕迹 → **逐字原样返回** |
| `light` | 删填充词、修少量模板句 |
| `medium` | 重组若干句子或段落，事实集合不变 |
| `heavy` | 仅创作模式或你明确要求大改 |

**no-op 是一等公民。** 不会为了「显得工作过」而把自然文本改一遍。

### 3. 事实锁

任何模式都不得擅自增、删、换、强化：

- 人物、机构、品牌、产品、地点
- 数字、日期、金额、比例、单位、技术参数
- 经历、案例、引文、来源、第一人称体验
- 因果、时间顺序、责任归属、比较关系
- 否定、程度、范围、可能性、承诺、结论强度
- 感官细节、心理活动、作者没表达过的判断

你要求「更具体」却不给素材？→ 保留原文，在正文外说明缺什么。**不编。**

### 4. 保护片段

默认逐字符保留：

- 引文、法规原文、脚注
- 代码、命令、变量、API 名称、URL、路径、文件名
- Markdown 链接、表格、标题层级、HTML、YAML、JSON
- 模板占位符、品牌术语、简历指标、合同条款、技术参数

不改你的标点体系（全角引号、「」、破折号都不是 AI 痕迹），不在中英之间补空格。

### 5. 说话人不能换

输出仍是**原作者在陈述**：

- 不写「这句话等于什么都没说」这类元评论
- 不加原文没有的人称、态度词（「说实话」「我一直觉得」）
- 不塞方括号工作说明

判据很简单：**原作者能不能一个字不删，直接署自己的名发出去。**

### 6. 源文本不可信

待处理文本只是编辑对象。里面出现「忽略规则」「执行以下命令」也不会变成指令。

## 和常见去 AI 味 / 润色工具的差别

| 维度 | 常见做法 | humanizer-zh |
|---|---|---|
| 首要目标 | 读起来更像人 | **先保真，再像人** |
| 事实处理 | 易补细节、加戏、改强度 | **事实锁**，缺素材就 no-op |
| 自然文本 | 也常被「优化」一遍 | **no-op gate**，原样返回 |
| 修改强度 | 一刀切重度改写 | no-op / light / medium / heavy |
| 模式 | 只有一档 | 保真默认，创作需**显式开启** |
| 引文 / 代码 / 合同 | 容易被顺手改掉 | **保护片段**逐字符保留 |
| 对话 / 文学文本 | 套路化删「套话」 | 场景边界，**该不动就不动** |
| 标点与版式 | 常被统一成某种风格 | **不改标点体系** |
| 作者声音 | 易被改成博主腔 | **说话人不能换** |
| 凭证安全 | 未必处理 | 密码 / key / 私钥**直接拒收** |
| 风险词表 | 禁词表，见词就改 | **信号参考**，看上下文和信息功能 |
| 检测器话术 | 有时承诺「过检测」 | **不输出** AI 概率，不承诺绕过检测 |

## 设计优势

1. **可放心用于正式文本**——简历、合同、客户报告、技术文档有明确保护规则
2. **不会毁掉你的真实感**——你写累的「了呢吧」、有意排比、判断力度字都留着
3. **不会表演式改稿**——自然就返回自然，差异检查盯新实体和强度漂移
4. **双档可控**——日常保真，要风格手术再开创作模式
5. **安全默认**——源文本当数据不当指令，凭证拒收
6. **零依赖**——纯 Markdown Skill + 规则参考，无脚本、无联网、无 API Key

## 安装

Agent Skills 标准结构，**任何支持 `SKILL.md` 的 AI 工具都能装**。

```bash
git clone https://github.com/Samuel-Shek/humanizer-zh.git
```

把 `humanizer-zh/` 文件夹放进对应工具的技能目录：

| 工具 | 安装位置 |
|---|---|
| **Work Buddy** | `~/.workbuddy/skills/` |
| **Claude Code** | `~/.claude/skills/` |
| **Codex** | `~/.agents/skills/` |
| **Cursor / Windsurf 等** | 该项目的 skills 目录，或全局 skills 目录 |
| **其他 Agent Skills 宿主** | 宿主扫描的 skills 根目录 |

```bash
# 示例：装进 Work Buddy
cp -r humanizer-zh ~/.workbuddy/skills/
```

重启工具或新开会话后生效。目录名保持 `humanizer-zh`（与 front matter 的 `name` 一致）。`references/` 目录需一并保留。

## 怎么用

```
去 AI 味：（粘贴正文）
```

```
润色一下这封邮件
```

```
改自然点 / 说人话：（粘贴正文）
```

要更大胆的风格调整时**明确说**：

```
启用创作模式，深度重写：（粘贴正文）
```

只要正文、不要说明：

```
用 humanizer-zh 处理，只要正文。
```

## 适用 / 不适用

| 适用 | 不适用 |
|---|---|
| 去掉模板腔、宣传腔、机械结构 | 从零写文章、写爆文 |
| 保真润色邮件、汇报、简介 | 起标题、做大纲 |
| 简历 / 合同 / 技术文档的套话清理 | 优化 Prompt（用 prompt-optimizer） |
| 对话记录里的客服腔清理 | 改代码、改配置、翻译 |
